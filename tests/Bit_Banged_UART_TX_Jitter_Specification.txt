Bit-Banged UART TX Jitter Specification Summary
Bare-Metal TX-Only UART

Recommended Timing Specifications
---------------------------------
1. Average baud-rate error:
   - Recommended: <= +/-1%
   - Preferred: <= +/-0.5%

2. TX bit-edge timing jitter:
   - Design target: <= +/-1% of the nominal bit period
   - Preferred implementation target: <= +/-0.5%
   - Absolute practical maximum: <= +/-2%
   - Avoid exceeding +/-3%, since receiver timing margin is reduced significantly

3. Start and stop bit treatment:
   - The falling edge that begins the start bit is normally the timing reference for the UART character.
   - Its absolute timing relative to the software transmit request is usually not included in the UART jitter specification.
   - If needed, TX request-to-start-bit latency should be specified separately.
   - The duration of the start bit IS part of the UART bit-timing requirement.
   - All data-bit boundaries and the transition into the stop bit should meet the same timing-jitter specification.
   - The stop bit should remain HIGH for at least the required minimum duration before another start bit begins.

Recommended Formal Requirement
------------------------------
"Software UART TX Timing:
Nominal transmitted bit duration shall be within +/-1% of the configured baud rate.
Individual transmitted bit-edge timing jitter shall not exceed +/-2% of one nominal
bit period, with a design target of +/-1% or better."

For frame-based timing verification:
- Define t0 as the falling edge of the START bit.
- Measure all subsequent bit boundaries relative to t0.
- Recommended requirement:

      tn = n * Tbit +/- 1% of Tbit

- This should include:
  * Start-bit duration
  * Each data-bit duration
  * Transition into the stop bit
  * Minimum stop-bit duration

Stop-Bit Requirement
--------------------
A useful minimum requirement is:

    Tstop >= Tbit * (1 - allowed timing error)

For a +/-1% requirement:

    Tstop >= 0.99 * Tbit

Preferably, the transmitter should provide at least one full nominal bit period of
HIGH level for the stop bit.

Example: 115200 Baud
--------------------
Nominal bit period:

    Tbit = 1 / 115200 = 8.6806 us

Equivalent timing errors:

    +/-0.25% = +/-21.7 ns
    +/-0.5%  = +/-43.4 ns
    +/-1.0%  = +/-86.8 ns
    +/-2.0%  = +/-173.6 ns
    +/-3.0%  = +/-260.4 ns

At a 48 MHz CPU/timer clock:

    1 clock = 20.83 ns

Therefore, +/-1% timing error at 115200 baud corresponds to approximately:

    86.8 ns / 20.83 ns = 4.2 CPU clocks

Implementation Guidance
-----------------------
For a bare-metal implementation, a hardware timer should be used whenever
possible rather than software delay loops.

Preferred architecture:

    GPT or AGT timer
        -> compare event / timer interrupt
        -> GPIO update

An absolute-deadline scheduling approach is preferred. Each bit transition should
be scheduled against the original frame timing reference rather than by applying a
relative delay after the previous transition. This prevents interrupt or execution
latency from accumulating across the UART character.

Avoid relying on simple software delay loops because timing can be affected by:
- Interrupt latency
- Flash wait states
- Compiler optimization
- Branch execution timing
- GPIO register-access timing

Recommended Design Target for RA2E3
-----------------------------------
A good practical specification is:

    Baud accuracy:          <= +/-1%
    Edge jitter target:     <= +/-1% of Tbit
    Edge jitter maximum:    <= +/-2% of Tbit
    Preferred target:       <= +/-0.5% of Tbit
    Stop-bit duration:      >= 0.99 * Tbit, preferably >= 1.0 * Tbit

With timer-based scheduling and controlled interrupt behavior, the MCU may be
capable of substantially better timing than the formal requirement.
